# Architecture — module documentation

Spring Modulith–generated documentation of the platform's bounded-context modules. This is a
committed snapshot; it is regenerated by the `ModularityTests.writesModuleDocumentation()` test into
`target/spring-modulith-docs/` on every `./mvnw test`.

## Files

| File | What it is |
|---|---|
| `components.puml` | C4 **component diagram** of all modules and their dependencies |
| `module-<name>.puml` | Per-module component diagram |
| `module-<name>.adoc` | Per-module **canvas** (spring beans, exposed types, dependencies) |
| `all-docs.adoc` | Aggregate AsciiDoc including every module canvas |

Render the `.puml` files with any PlantUML tool — the VS Code *PlantUML* extension,
<https://www.plantuml.com/plantuml>, or `plantuml *.puml`.

## Reading the diagram

The nine bounded-context modules are: **shared** (kernel), **identity**, **organization**,
**catalog**, **sales**, **messaging**, **notifications**, **governance**, and **ui** (the single
Vaadin driving adapter). Each follows the canonical hexagonal layout
`domain / application(port.in, port.out, service) / adapter(out.*)`.

Two extra modules — **Core** and **Infrastructure** — are *transitional leftovers* of the migration
(published-language DTOs + mappers + `ISystemMetrics` in `Core.Application`, the appointment types
in `Core.Domain.users`, and cross-cutting technical infrastructure such as the AOP aspects,
`WsepHttpClient`, schedulers, and seeding). They disappear as that leftover content is assigned to
its owning context or the shared kernel.

## Enforcement status

- **ArchUnit hexagonal rules** (`HexagonalRulesTest`) are **enforced** now: the domain is free of
  Spring/Vaadin and the outer layers, the application layer never depends on adapters, and no backend
  context depends on `ui`.
- **Strict Modulith `verify()`** (`ModularityTests.verifiesModuleBoundaries`) is **disabled** until
  the deferred behavioural rewiring breaks the intentional transitional cross-context *cycles* (e.g.
  catalog↔sales): the inventory-ownership port on catalog, event-driven notifications, and the
  governance market-gate port. Modulith rejects cycles, and cycles cannot be waived by declaring
  allowed dependencies — so `verify()` waits on that work rather than being forced green.
